# 作品交付格式

本課程的作品會分成兩種：單元一的**程式狀態報告**，以及單元二的**校園提示系統**。兩份記錄都重視「規則是否清楚」和「如何測試」，而不只是最後畫面。

## 單元一：課室環境狀態報告

請交付程式截圖或文字、Serial Monitor 結果截圖，以及以下內容：

| 項目 | 你要交代甚麼？ |
| --- | --- |
| 使用的資料 | 至少兩個變數及其數值，例如溫度、座位數 |
| 判斷規則 | 哪個 `if` 條件會顯示哪一個狀態？ |
| 重複工作 | `for` 會由哪個數字開始、到哪個數字結束？ |
| 硬件轉換計劃 | 下一單元想用甚麼輸出元件代表程式結果？ |

## 單元二：校園提示系統

請把以下內容整理成一份簡短作品記錄，可使用教師指定的文件、簡報或班級平台交付。

### 1. 作品資料

- 作品名稱：
- 設計者：
- 校園情境：
- Tinkercad 分享連結（如適用）：

### 2. 狀態規則

用表格說明每個燈號代表甚麼，而不是只寫「紅黃綠輪流亮」。

| 狀態 | 亮起的 LED | 人應怎樣理解？ |
| --- | --- | --- |
| 例：暫停進入 | 紅燈 | 正在進行實驗，請在外等候 |

### 3. 測試紀錄

| 我測試了甚麼？ | 原本看到甚麼？ | 我怎樣修正或確認？ |
| --- | --- | --- |
| 例：黃燈是否只亮 1 秒 | 黃燈與紅燈同時亮 | 檢查 `digitalWrite()`，補上把紅燈關閉的指令 |
