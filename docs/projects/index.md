# 作品交付格式

本課程的作品分成兩種：單元一的**程式狀態報告**，以及單元二的**校園提示系統**。兩份記錄都重視「規則是否清楚」和「如何測試」，而不只是最後畫面。

## 單元一：課室環境狀態報告

請交付程式截圖或文字、Serial Monitor 結果截圖，以及以下內容：

| 項目 | 你要交代甚麼？ |
| --- | --- |
| 使用的資料 | 至少兩個變數，當中有一個小數資料，例如溫度 |
| 判斷規則 | 哪個 if 條件會顯示哪一個狀態？ |
| 重複工作 | for 會由哪個數字開始、到哪個數字結束？ |
| 整理方法 | 你建立的函式叫甚麼？它負責哪一組工作？ |
| 硬件轉換計劃 | 下一單元想用甚麼 LED 回應這個文字結果？ |

## 單元二：校園提示系統

請把以下內容整理成一份簡短作品記錄，可使用教師指定的文件、簡報或班級平台交付。

### 1. 作品資料

- 作品名稱：
- 設計者：
- 校園情境：
- Tinkercad 分享連結（如適用）：

### 2. 規則與燈號

先寫出程式會判斷甚麼，再說明每個燈號代表甚麼。

| 程式狀態／規則 | 亮起的 LED | 人應怎樣理解？ |
| --- | --- | --- |
| 例：實驗正在進行 | 紅燈 | 暫停進入，請在外等候 |
| 例：即將完成準備 | 黃燈 | 請稍候 |
| 例：可以進入 | 綠燈 | 可安全進入 |

### 3. 測試紀錄

| 我測試了甚麼？ | 原本看到甚麼？ | 我怎樣修正或確認？ |
| --- | --- | --- |
| 例：警示狀態會否亮紅燈 | Serial Monitor 顯示警示，但紅燈不亮 | 發現程式用 D9、導線接 D10；改回 D9 後成功 |

### 4. 圖片

附上一張清楚看到電路與模擬正在運行的截圖。若圖片無法同時顯示程式狀態，請加上一張 Serial Monitor 截圖或附上 Tinkercad 分享連結。

::: tip 拍攝提示
可參考〈[Tinkercad 截圖清單](/resources/tinkercad-screenshot-list)〉；最重要的是讓別人看見**哪個狀態正在發生**，而不只是看見一堆元件。
:::
