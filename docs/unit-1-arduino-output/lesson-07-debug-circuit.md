# 第 7 課：裝置不動時，怎樣找問題？

## 今課可以做到甚麼？

- 分辨問題可能來自元件、接線、腳位或程式。
- 用「一次只檢查一件事」的方法縮小問題範圍。
- 留下一段別人看得懂的除錯紀錄。

## 開始前：想一想

如果三盞燈都不亮，直接重寫整段程式，通常未必最快。你會先檢查電腦裡的程式，還是先看 LED 是否接反？為甚麼？

## 新概念：由最小測試開始

![除錯檢查清單](/images/debug-check.svg)

不要一次改五個地方，否則即使最後成功，也不知道真正的原因。可以依照以下順序：

1. 元件：是否真的放了正確元件？
2. 回路：是否有電阻、方向和 GND？
3. 腳位：接線號碼是否與程式一致？
4. 程式：先用最短的亮燈程式測試。

## 跟著做：把三燈系統拆開檢查

先暫時只保留紅燈和最短程式：

```cpp
const int redLed = 10;

void setup() {
  pinMode(redLed, OUTPUT);
  digitalWrite(redLed, HIGH);
}

void loop() {
}
```

如果紅燈亮，表示 Arduino、腳位 10、紅燈回路基本上可用。再逐一加回黃燈和綠燈。

## 再試一次：寫一條有證據的紀錄

不要只寫「修好了」。請寫：

> 原本：綠燈一直不亮。
> 檢查：程式使用 `greenLed = 8`，但電線實際接到 7 號腳位。
> 修正：把接線改回 8 號，單獨測試後再加回其他燈。

這樣下次遇到類似問題，自己和同學都能重現檢查方法。

## 易錯位

| ✕ 錯誤 | 為甚麼 | 修正方法 |
| --- | --- | --- |
| 一次改接線、程式和時間 | 沒法知道哪個改動有效 | 一次只改一件事 |
| 只看 LED，不看程式腳位 | 電路與程式是一對 | 把腳位表和程式放在一起核對 |
| 看見紅色錯誤訊息就重寫全部 | 錯誤可能只是少了分號 | 先讀錯誤指出的行附近 |
| 沒有記錄測試 | 下次只能重新猜 | 寫下原本、檢查、修正和結果 |

## 你來做

- **基礎題**：故意把一盞 LED 接錯腳位，再用清單找回問題。
- **標準題**：將一段三燈程式拆成三次單獨測試。
- **挑戰題**：請同學只看你的除錯紀錄，說出你怎樣找到問題。

## 本課小結

- 除錯不是亂試，而是縮小問題範圍。
- 元件、接線、腳位和程式要逐項核對。
- 一份好的紀錄要包含原本現象、檢查證據、修正和結果。
