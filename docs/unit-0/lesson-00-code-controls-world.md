# 第 0 課：程式如何控制現實世界？

## 今課可以做到甚麼？

- 說出一個互動系統怎樣「感知、判斷、回應」。
- 從自動門、交通燈或校園設備中找出輸入、規則和輸出。
- 說出為甚麼會先用文字輸出測試程式，再接上硬件。

## 開始前：想一想

自動門看見有人靠近才打開；交通燈依照時間改變；校園鐘在指定時間響起。它們不是「自己知道要做甚麼」，而是按照已寫好的規則工作。

如果要設計一盞「實驗進行中」提示燈，你覺得它要知道甚麼？又應該怎樣回應？

## 一個互動系統的三件事

![感知、判斷、回應的系統圖](/images/input-process-output.svg)

- **感知**：收到現實世界的資料，例如按鈕被按下、光線變暗、距離變近。
- **判斷**：程式按規則決定下一步，例如「如果光線不足，就開燈」。
- **回應**：讓燈、蜂鳴器、螢幕或馬達做出動作。

## 先把規則看清楚，再讓硬件執行

如果 LED 沒有亮，可能是程式條件寫錯，也可能是 LED 接反、電阻漏接或腳位不一致。初學時同時處理兩類問題，往往很難找出原因。

因此，課程先把程式結果印在 **Serial Monitor**：

```text
溫度偏高：建議通風
```

當你已看清楚變數、`if` 和循環能產生正確結果，下一步才把這一句文字變成燈號或其他硬件回應。這樣每一次測試都有清楚的目的。

## 跟著看：同一條規則，兩種呈現

| 程式判斷結果 | 單元一：螢幕上先看見 | 單元二：硬件再回應 |
| --- | --- | --- |
| 光線不足 | `需要開燈` | LED 亮起 |
| 溫度偏高 | `建議通風` | 紅燈亮起或提示燈閃爍 |
| 活動即將開始 | `倒數 3、2、1` | 燈號按節奏改變 |

## 你來做

1. 選一件校園內會「自動回應」的設備。
2. 用三句話寫下：它感知甚麼？按甚麼規則判斷？最後怎樣回應？
3. 再想一想：如果暫時沒有硬件，你會先在螢幕上顯示哪一句文字，來證明規則已經寫好？

## 本課小結

- 互動系統把現實世界的訊號，變成裝置的動作。
- 一個系統通常包含感知、判斷和回應。
- 先在文字輸出驗證規則，再接上硬件，會較容易找錯和修改。

## 離堂前 3 分鐘

2. 「如果按鈕被按下，就亮燈」中，哪一部分是程式的規則？
3. 為甚麼本課程不會一開始就要求接好完整 LED 電路？
