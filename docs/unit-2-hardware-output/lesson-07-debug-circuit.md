# 第 14 課：LED 不如預期時，怎樣找問題？

## 今課可以做到甚麼？

- 分辨程式規則問題、腳位不一致和電路回路問題。
- 用「先看文字、再測一盞燈」的方法縮小問題範圍。
- 留下一段別人看得懂的除錯紀錄。

## 開始前：想一想

三盞燈都不亮時，直接重寫三燈程式通常不是最快的方法。上個單元已學會：先把中間資料印出來。硬件加入後，這個習慣仍然有用嗎？

## 由文字規則走到一盞 LED

遇到問題時，按這個順序檢查：

1. **文字結果**：Serial Monitor 是否顯示預期狀態？
2. **程式腳位**：例如 `const int warningLed = 9;` 是否與導線一致？
3. **一盞最小測試燈**：先只接一盞 LED，寫最短亮燈程式。
4. **回路細節**：電阻有沒有串聯？LED 有沒有接反？最後有沒有回到 GND？
5. **逐一加回**：一盞燈成功後，才加下一盞。

## 跟著做：把三燈系統拆成一盞測試

先暫時只保留警示燈與最短程式：

~~~cpp
const int warningLed = 9;

void setup() {
  Serial.begin(9600);
  pinMode(warningLed, OUTPUT);
  Serial.println("正在測試 D9 警示燈");
  digitalWrite(warningLed, HIGH);
}

void loop() {
}
~~~

如果 Serial Monitor 顯示測試文字、LED 也亮，表示 Arduino、D9、電阻、LED 方向和 GND 回路大致可用。再逐一加回其他燈與狀態函式。

## 再試一次：寫一條有證據的紀錄

> 原本：警示狀態在 Serial Monitor 已正確顯示，但紅燈一直不亮。
> 檢查：程式設定 warningLed = 9，導線卻接到 D10。
> 修正：把導線移到 D9，先用一盞燈最小程式測試，再加回完整狀態程式。
> 結果：紅燈會在警示狀態亮起，綠燈保持熄滅。

## 易錯位

| ✕ 錯誤 | 為甚麼 | 修正方法 |
| --- | --- | --- |
| 一次改接線、程式和時間 | 沒法知道哪個改動有效 | 一次只改一件事 |
| 只看 LED，不看 Serial Monitor | 看不出規則是否已正確執行 | 先保留文字狀態作檢查 |
| 看見錯誤訊息就重寫全部 | 問題可能只是少了分號或腳位不同 | 先讀錯誤行與設定區 |
| 三盞燈壞了仍同時測三盞 | 問題範圍太大 | 拆成一盞燈的最小測試 |

## 你來做

- **基礎題**：故意把一盞 LED 的導線接到錯誤腳位，再用清單找回問題。
- **標準題**：把三燈程式拆成三次單獨亮燈測試。
- **挑戰題**：請同學只看你的除錯紀錄，說出你怎樣找到問題。

## 本課小結

- 先確認文字規則，再檢查硬件輸出。
- 最小測試可快速縮小問題範圍。
- 一份好的除錯紀錄要包含現象、證據、修正和結果。
