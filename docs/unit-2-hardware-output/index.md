# 單元二：讓硬件回應程式

## 單元最後會完成甚麼？

你會在 **Tinkercad Circuits** 把單元一已驗證過的程式規則，接到 LED 與電路，完成一個可運行的「校園提示系統」。作品不是隨意令燈閃爍，而是先由資料和規則決定狀態，再用燈號讓人看見結果。

![單元二硬件實作路線](/images/unit-one-roadmap.svg)

## 這個單元和單元一怎樣接上？

單元一已在 Serial Monitor 顯示：

~~~text
狀態：溫度偏高，建議通風
~~~

本單元保留同一條規則，再逐步把它改成：

| 已驗證的文字結果 | 硬件回應 |
| --- | --- |
| 溫度偏高，而且課室有人 | 紅色 LED 亮起 |
| 狀態合適 | 綠色 LED 亮起 |
| 需要立即注意 | LED 按節奏閃爍 |

每次接上新硬件前，仍可以先用 Serial Monitor 印出資料或狀態。這樣當 LED 沒有如預期亮起時，你能分辨：是**規則還未寫對**，還是**接線／腳位有問題**。

## 八課地圖

| 課次 | 要解答的問題 | 核心成果 |
| --- | --- | --- |
| 第 8 課 | Tinkercad 怎樣延續已驗證的程式？ | 在新 Circuit 重現 Serial Monitor 的狀態結果 |
| 第 9 課 | 一盞由程式控制的 LED 要怎樣接？ | D8 → 電阻 → LED → GND 的完整回路 |
| 第 10 課 | 怎樣把 if 的文字結果變成兩種燈號？ | 按條件亮紅燈或綠燈 |
| 第 11 課 | 怎樣把「需要注意」變成有節奏的訊號？ | 會閃爍的提示燈與文字測試紀錄 |
| 第 12 課 | 三盞燈怎樣清楚表示狀態？ | 一次只亮一種狀態的三燈系統 |
| 第 13 課 | 怎樣令接線和程式更容易修改？ | 有意義的腳位名稱與狀態函式 |
| 第 14 課 | 燈號不如預期時怎樣找問題？ | 有步驟的程式＋電路除錯紀錄 |
| 第 15 課 | 怎樣把技術放入校園情境？ | 校園提示系統專題 |

## 最後作品的完成標準

- [ ] Tinkercad 模擬含 Arduino Uno、至少三盞 LED 和每盞 LED 對應的電阻。
- [ ] 每盞 LED 都有完整回路與 GND 路徑。
- [ ] 程式先根據清楚規則決定狀態，再輸出到燈號。
- [ ] 程式使用有意義的腳位名稱與至少一個狀態函式。
- [ ] 交付一張模擬運行截圖或 Tinkercad 分享連結。
- [ ] 用 80 至 120 字交代情境、燈號規則和一次測試／修正。

::: warning 安全提醒
本單元使用**線上模擬**，不需要接觸真實電源或焊接。日後使用實體 Arduino 時，必須按教師指示接線，切勿把 LED 直接長時間接在電源兩端。
:::
