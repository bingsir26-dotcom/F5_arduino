# 單元二：讓硬件回應程式

## 單元最後會完成甚麼？

你會在 **Tinkercad Circuits** 把單元一已經寫好的程式邏輯，接到 LED 和其他輸出元件，完成一個可運行的「校園提示系統」：先由程式決定狀態，再由硬件把狀態顯示出來。

![單元二硬件實作路線](/images/unit-one-roadmap.svg)

## 這個單元和單元一怎樣接上？

單元一先在 Serial Monitor 顯示：

```text
狀態：溫度偏高，建議通風
```

本單元會把同一個結果改成硬件回應，例如：

- 「溫度偏高」→ 紅色 LED 亮起。
- 「溫度合適」→ 綠色 LED 亮起。
- 「請注意」→ LED 按節奏閃爍，或配合蜂鳴器提示。

因此，你不是重新學一套完全無關的內容，而是把已經測試過的程式規則，逐步接到真實可見的輸出。

## 最後作品的完成標準

- [ ] Tinkercad Circuits 模擬含有 Arduino Uno、至少三盞 LED 和每盞 LED 對應的電阻。
- [ ] 每盞 LED 都有清楚、完整的回路與 GND 路徑。
- [ ] 硬件回應能對應到清楚的程式狀態，例如「正常／注意／停止」。
- [ ] 程式使用有意義的腳位名稱，例如 `redLed`、`quietLed`。
- [ ] 燈號有清楚的狀態規則，不只是隨意閃爍。
- [ ] 交付一張模擬截圖或 Tinkercad 分享連結。
- [ ] 用 80 至 120 字交代情境、燈號規則和一次測試／修正。

::: warning 安全提醒
本單元使用**線上模擬**，不需要接觸真實電源或焊接。日後使用實體 Arduino 時，必須按教師指示接線，切勿把 LED 直接長時間接在電源兩端。
:::
