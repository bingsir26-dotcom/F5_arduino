# 第 6 課：程式不如預期時，怎樣找問題？

## 今課可以做到甚麼？

- 分辨「程式不能開始」與「程式開始了但結果不對」。
- 用固定步驟檢查分號、括號、拼寫和比較符號。
- 利用 Serial Monitor 印出中間資料，找出規則錯在哪裡。

## 開始前：想一想

以下程式只差一個字元，卻不能開始模擬。你會把整段程式重寫，還是先找錯誤訊息指向的位置？

~~~cpp
int usedSeats = 26
~~~

程式錯誤不是失敗紀錄；它是在告訴我們哪個地方需要再看一次。

## 先分清兩種問題

| 看到的情況 | 先怎樣想 | 例子 |
| --- | --- | --- |
| 模擬不能開始，出現紅色錯誤訊息 | 格式或拼寫可能有問題 | 少了 `;`、括號不成對、名稱拼錯 |
| 模擬能開始，但顯示結果不對 | 資料或規則可能有問題 | 條件寫反、使用了舊數值 |

![程式除錯檢查圖](/images/debug-check.svg)

## 跟著做：找出四個小錯誤

~~~cpp
int usedSeats = 26
float temperature = 28.5;

void setup() {
  Serial.begin(9600);
  if (temperature = 28.5) {
    Serial.println("溫度偏高")
  }
}

void loop() {
}
~~~

請找出：少了兩個 `;`、`temperature = 28.5` 是放入資料而非比較，以及規則應改為 `temperature > 26`。

修正後：

~~~cpp
if (temperature > 26) {
  Serial.println("溫度偏高");
}
~~~

## 再試一次：把中間資料印出來

程式能開始但狀態不對時，先顯示要判斷的資料：

~~~cpp
Serial.print("目前溫度：");
Serial.println(temperature);
~~~

如果畫面顯示的不是預期數值，先檢查變數資料；資料正確才檢查 `if` 條件。

## 易錯位

| ✕ 錯誤 | 為甚麼 | 修正方法 |
| --- | --- | --- |
| 看到錯誤訊息就刪掉整段 | 會失去原本可用部分 | 先看訊息指出的行與前一行 |
| 用 `=` 比較是否相等 | `=` 是把資料放入變數 | 比較才用 `==`；大小比較用 `>`、`&lt;` |
| 只看最後一句輸出 | 看不出資料在哪步變錯 | 顯示中間變數作檢查 |
| 一次改很多地方 | 成功後也不知道原因 | 一次修正一種問題，再開始模擬 |

## 你來做

- **基礎題**：修正 `Serial.println("你好")` 的格式錯誤。
- **標準題**：把 `temperature > 26` 改成 `temperature < 26`，預測輸出後再修正。
- **挑戰題**：為第 3 課程式加入兩行中間資料輸出。

## 本課小結

- 先分辨是語法錯誤，還是邏輯結果不對。
- 分號、括號、拼寫與 `=`／`==` 是最常見的檢查位。
- 顯示中間資料，是找出規則問題的好方法。
